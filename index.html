Overview

The FloodWatch API exposes real-time flood sensor data collected from ESP32 river nodes deployed in Sarawak, Malaysia. Nodes report battery voltage, GPS location, and water level via LoRa 433 MHz to a master gateway, which forwards readings to an MQTT broker (Fly.io Singapore). A parser service writes every reading to MongoDB Atlas. This API reads from that database.

There are two ways to consume data: REST for querying stored history, and Server-Sent Events (SSE) for receiving live pushes as new readings arrive.

CORS & Auth

All endpoints accept requests from any origin (Access-Control-Allow-Origin: *). No API key or authentication is required — all data is publicly readable.

Server-Sent Events

Connect to /api/v1/events using the browser's built-in EventSource API or any SSE client library. The server streams events as new sensor readings arrive (polled every ~2 seconds).

SSE endpoint
GET /api/v1/events?types=heartbeat,flood_level,battery_low

The types query parameter is a comma-separated filter. Omit it to receive all event types. 
const es = new EventSource("http://<API_HOST>:8000/api/v1/events");

es.addEventListener("heartbeat", e => {
  const { node_id, timestamp } = JSON.parse(e.data);
  console.log(`[heartbeat] ${node_id} alive at ${timestamp}`);
});

es.addEventListener("flood_level", e => {
  const { node_id, water_level, lat, lng } = JSON.parse(e.data);
  console.warn(`[flood] ${node_id} — level ${water_level} at (${lat}, ${lng})`);
});

es.addEventListener("battery_low", e => {
  const { node_id, voltage } = JSON.parse(e.data);
  console.warn(`[battery] ${node_id} — ${voltage}V (low)`);
});

es.onerror = () => console.error("SSE connection lost, browser will retry");
import { useEffect } from "react";

export function useFloodWatch(apiBase, onEvent) {
  useEffect(() => {
    const es = new EventSource(`${apiBase}/api/v1/events`);
    ["heartbeat", "flood_level", "battery_low"].forEach(type =>
      es.addEventListener(type, e => onEvent(type, JSON.parse(e.data)))
    );
    return () => es.close();
  }, [apiBase]);
}

Event: heartbeat

Emitted for every new reading received from any node regardless of flood status. Use this to confirm a node is alive and sending.

heartbeat 
event: heartbeat
data: {"node_id": "SUTS_White", "timestamp": "2026-05-06T14:32:11.045000+00:00"}
FieldTypeDescription
node_idstringNode identifier
timestampISO 8601UTC time the reading was received by the parser

Event: flood_level

Emitted when a reading has water_level > 0. Nodes report 1 ft, 2 ft, or 3 ft via three physical float sensors.

flood_level 
event: flood_level
data: {
  "node_id":     "SUTS_White",
  "water_level": 2,
  "float_bits":  "010",
  "lat":         1.559200,
  "lng":         110.359000,
  "timestamp":   "2026-05-06T14:32:11.045000+00:00"
}
FieldTypeDescription
water_level1 | 2 | 31 = 1 ft, 2 = 2 ft, 3 = 3 ft
float_bitsstringRaw 3-bit sensor state (bit0=3ft, bit1=2ft, bit2=1ft)
lat / lngnumberNode GPS coordinates (may be 0.0 if no GPS fix yet)

Event: battery_low

Emitted when a node reports a voltage below 11.5 V (threshold for a 12 V lead-acid battery). Nodes send voltage with every reading.

battery_low 
event: battery_low
data: {
  "node_id":   "SUTS_White",
  "voltage":   10.82,
  "threshold": 11.5,
  "timestamp": "2026-05-06T14:32:11.045000+00:00"
}
FieldTypeDescription
voltagenumberMeasured voltage in volts (V)
thresholdnumberConfigured low-battery threshold (default 11.5 V)

Reading object

All REST endpoints return reading objects with the following fields.

FieldTypeNullableDescription
node_idstringUnique node identifier stored in ESP32 flash
latnumberGPS latitude (0.0 if no fix)
lngnumberGPS longitude (0.0 if no fix)
float_bitsstringnull3-char binary: "101" means 3ft + 1ft active
water_level0 | 1 | 2 | 3nullHighest active float (0 = no water)
voltagenumberBattery voltage in volts (12V system)
raw_adcintegerRaw 12-bit ADC reading (0–4095)
rssiintegernullLoRa signal strength in dBm (appended by master gateway)
timestampISO 8601UTC time the parser received and stored the reading
float_bits vs water_level
float_bits is the raw 3-bit string from the node ("bit2 bit1 bit0" = 3ft / 2ft / 1ft). water_level is the computed integer: highest triggered sensor. Both are null for black nodes (no float sensors).
